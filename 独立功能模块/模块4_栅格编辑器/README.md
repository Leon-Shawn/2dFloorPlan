# 模块 4 · 栅格地图编辑器

> 《软件工程理论基础》课程设计 · 选题 15「2D 户型全覆盖清扫仿真」
> 角色：**基础模块** · 独立提交包

---

## 这个包做什么

让人**手工修正**模块 1 的解析结果，并给出连通性诊断。

## 为什么需要它（工程刚需，不是凑数）

模块 1 的图像解析不可能 100% 准确。没有编辑器，一次解析错误就导致
覆盖率数字完全失真、演示当场翻车；有了编辑器，任何解析错误都能在
30 秒内人工修正。

**它把「看运气」的项目变成「必可救」的项目。**

这也是最强的演示抓手：现场用橡皮擦掉一个门洞 → 覆盖率从 100% 掉到 92%
→ 补回来 → 回到 100%。这一个动作同时证明了自主性、鲁棒性和对核心指标的理解。

## 目录结构

```
backend/
├── api/
│   ├── module4.py         186 行  编辑器接口（新建/校验/预置地图）
│   └── common.py          103 行  栅格反序列化公共入口
├── planning/
│   └── grid_ops.py        136 行  连通域标记、BFS 可达性、包围盒
├── core/
│   ├── rasterize.py              GridCell 定义（依赖模块 1 的栅格格式）
│   └── binarize.py
├── app/main.py                     独立服务入口
└── data/floorplans/               模块 1 的示例图（供联调，非本模块功能）
```

## 关于 core/ 目录

本包内附 `core/rasterize.py` 与 `core/binarize.py`，
**但它们在这里只提供 `GridCell` 常量与栅格构造工具**——
模块 4 依赖模块 1 产出的栅格格式，不附的话包跑不起来。
这部分**不计入模块 4 的功能量**。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/editor/grid` | 新建空白栅格 |
| POST | `/api/editor/validate` | 校验并给连通性诊断 |
| GET | `/api/editor/presets` | 列出 4 张预置地图 |

## 内置预置地图

| 名称 | 用途 |
| --- | --- |
| L 形开放空间 | 单一连通域，基准场景 |
| 三室两门 | 两处门洞决定连通性 |
| 含孤立房间 | 右上角房间无门，**必然漏扫**（用于演示归因） |
| 窄通道 | 1 格通道，验证机身半径约束 |

后两张是**故意设计的反例**，用来证明覆盖率掉下来时能区分
「地图断了」和「算法漏了」——这是 BFS 可达性分析的价值所在。

## 跑起来

```bash
pip install -r requirements.txt
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

冒烟验证：

```bash
curl http://127.0.0.1:8000/api/health
curl -X POST http://127.0.0.1:8000/api/editor/grid \
     -H "Content-Type: application/json" -d '{"width":12,"height":12}'
curl http://127.0.0.1:8000/api/editor/presets
```

## 不包含什么

- 模块 1 图像解析（仅保留 `GridCell` 常量）
- 模块 3 路径规划
- 前端页面（`frontend/`）——Canvas 渲染与绘制工具在完整项目里
